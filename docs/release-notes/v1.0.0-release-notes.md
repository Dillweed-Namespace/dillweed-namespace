# Dillweed Namespace v1.0.0

**Released:** 2026-05-17

This is the v1 baseline release of the Dillweed Namespace. It bundles three independently-versioned components that together implement the v1 specification, each individually audit-cycled by external review and validated on the reference deployment.

The tarballs are attached to this release as downloadable assets.

## What's in v1

**Specification conformance** — all three components implement the v1 specifications published at [dillweed.com](https://dillweed.com). Specifications were finalized 2026-05-16 with the publication of five spec documents (Namespace, Registry, DillClaw Resolver, Anthill, and Trust Architecture).

**Trust root** — the canonical DNSO public key is published at `https://dillweed.com/dnso_public.pem` with SHA256 `909891e92cfa7362ee88fd75e85f379a317680a2c987fc4d88ecae150deb6f33`. The Resolver v0.1.8 installer fetches this automatically; no manual key placement is required.

**External audit** — each component went through multiple rounds of external review before reaching v1 baseline:
- Registry: 5 review rounds, converged at v0.2.7 ship-equivalence
- Resolver: 3 review rounds + final-pass addendum, converged at v0.1.7
- Anthill: 3 review rounds, converged at v0.1.4

**Install testing** — three install modes exercised on `dill-p-001` (macOS 26.5, Node.js v22.22.2): in-place upgrade, uninstall, and clean install from pristine tarballs. Testing surfaced the issues that drove the v1 patch round.

**v1 patch round** — three follow-up patches address findings from install testing:

| Patch | Closes | Description |
|---|---|---|
| Resolver v0.1.7 → v0.1.8 | INST-004 (HIGH) | Installer now fetches the canonical DNSO public key from `dillweed.com` at install time instead of shipping a (wrong) bundled key |
| Registry v0.2.7 → v0.2.8 | INST-001 (LOW), INST-005 (MEDIUM) | `install.sh` aborts cleanly if run from inside the install destination; `test.sh` now supports `REGISTRY_ADMIN_TOKEN` env var |
| Anthill v0.1.4 → v0.1.5 | INST-006 (LOW) | `test.sh` now appends a per-run unique suffix to `originating_node` values so tests don't collide with preserved `node_sequences` high-water-marks after in-place upgrades |

The only HIGH-severity install finding (INST-004) is closed.

## Known issues

Carried into v1.0.0 (none HIGH or MEDIUM):

- **INST-008 (LOW)** — partial closure; the Resolver tarball filename was corrected from `dillclaw-resolver-v0.1.8.tar.gz` to `dillweed-resolver-v0.1.8.tar.gz` at v1.0.0 publication. The tarball still extracts to a `dillclaw-resolver/` directory (the component-internal name) — cosmetic inconsistency, queued for cleanup in a future release
- **INST-011 (info)** — admin tokens in launchd plist files are stored plaintext (acceptable for reference deployment)
- **INST-012 (info)** — Registry tarball ships unused `resolver-patch.js` artifact (cosmetic)
- **INST-013 (LOW)** — Anthill AS-006 body-size test method unreliable for 300KB payloads; server-side enforcement intact, only the test approach needs revision (queued for v0.1.6)

Full ledger: [`project-action-items.md`](../project-action-items.md).
